- Live component Providers are generation-owned siblings, never ancestors of core chat/composer. Originate feature portals beneath their Provider; same-owner nested slots retain local contexts. Git publishes detail/layout through the shared SDK bridge while core chat stays mounted across removal and updates.
- Installed `sidebarView` contributions are full-page destinations (`component:${packageName}`), not dock surfaces or separate selection state. Skills retains its persisted `skills` route explicitly. Workspace state owns selection; catalog admission owns availability. Keep page portals beneath their Provider and retain underlying work/composer scope when changing pages.
- Full renderer generations use the host React and SDK context identities through `component-module-bridge.ts`. Add any new SDK context owner to that bridge and `componentSharedModules` before bundling its public modules. Standalone `ui.tsx` still owns an independent root.
- Renderer utility CSS follows named DOM scopes, not React ancestry. Preserve scopes across slots, renderer-created portals, and shared SDK retained surfaces; nodes moved through a host registry need their owner captured before transport. Do not wrap portal children when the destination already has their owner scope: native shadow slots require direct children. Keep host ReactDOM unchanged outside the renderer bridge.
- Retained-surface metadata identities must not follow content renders. Memoise scoped actions independently of content: metadata publication can redraw Git presentation and the transcript, closing a feedback loop through turn attachments.
- Validate the entire public renderer contribution before acknowledging its exact generation. Unsupported shell routes and commands are errors, not partially ready components. Never acknowledge retired modules or reconnect by replaying an action.
- Runtime render/request failures stay local to their mounted boundary, with an explicit retry that remounts the feature. Do not report them as renderer admission failures and poison the shared installed generation; admission rejection belongs to module loading and contribution validation.
- `howcode.navigation: true` designates a navigation-only renderer (optional Provider); defer import until selected and reject independent features at admission. Mixed contributions retain peer capabilities when navigation changes. Catalogue inventory is the only activation authority: no distribution renderer fallback. Removing a generation leaves its saved navigation unavailable, with Settings reachable outside navigation.
- The Git API is an opaque SDK field with a feature-owned public contract. Validate every required callable before admission; its host-input Schema belongs to Git. Share the SDK `git-renderer` module identity with live bundles and clear bridge publications only for their owning generation.
- Forward peer draft text only to the registered Composer receiver for the current directory and conversation. Registration cleanup may release only its own receiver; core never writes Composer storage or submits on a peer's behalf.
- Composer action delegates need both editor-scope guards and per-action generation revocation: removing an action must revoke its retained callbacks without retiring peer actions or the editor. Dictation selection must resolve before mounting hooks; never choose the first of several providers or fall back from a missing explicit choice.
