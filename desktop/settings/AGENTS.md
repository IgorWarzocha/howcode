- Shell preferences live in SQLite's `app_preferences`, not Pi's `settings.json`. The versioned snapshot is the migration marker: validate existing global and already registered directory overrides before its single atomic write; invalid sources must identify their path and leave migration retryable. After the marker, new directories inherit global preferences without reading Pi files.
- Import from Pi copies only schema-owned shell keys (plus the explicit compaction/image aliases). Preference import must never write Pi files or import credentials, resource roots, packages, skills, instructions or theme resources; those have separate owners.
- Legacy migration must shallow-merge raw global/local objects before resolving aliases; independently normalizing each file changes existing workspace values when nested objects shadow one another.
- Actual profiles can contain the flat `shellPreferences` snapshot written before scoped migration. Upgrade those saved global values into the versioned envelope; do not discard them or require a version marker they never had.
- When changing `provider-config.ts`, check installed Pi's `model-config` and `provider-composer` contracts: `modelOverrides` modifies existing catalog entries (ignoring unknown IDs), preserves unspecified nested metadata, and must not replace the provider catalog or rewrite user configuration. Keep unsupported fields visibly rejected.
- Provider login uses Pi's `Models` and the shared `auth.json`; never return its credential result or raw provider errors over IPC. Serialize mutations through `provider-auth.ts`, including Pi-directory changes and shutdown; cancellation does not undo an already committed credential. Keep per-prompt abort handling, the browser lease, and the overall deadline when changing this bridge.
- ChatGPT login requires a stable installation UUID. Keep it in Howcode's preferences, independent of the selected Pi directory; OAuth callbacks run on the server, so preserve Pi's manual-code/redirect-URL prompts for remote browsers.
