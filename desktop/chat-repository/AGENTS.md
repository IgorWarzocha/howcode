- Repository leaves return Effects. Keep `databaseOperation` at synchronous public boundaries; never reenter that boundary from a transaction.
- The synchronous boundary deliberately prevents query sequences from interleaving. Keep async work out of repository operations; background Git migrations have a separate scoped lifetime.
- Use `withDatabaseTransaction` to preserve deferred locking. The Node adapter's default `BEGIN IMMEDIATE` is not equivalent.
- Schema initialization executes explicit SQL statements. Effect's unprepared query path still prepares one statement; it is not a multi-statement `exec` replacement.
- `workspace-organization.ts` owns universal workspace membership in `conversation_facts.workspace_id`; `chat_groups` retains saved workspace IDs. Core folder persistence supplies directory mappings at host composition; Sidebar owns worktree associations with their root workspace. Discovery and reconciliation must not create workspaces from remembered directories; only an explicit folder-add/create action creates a directory workspace.
- Legacy membership migration must preserve explicit workspace membership, conversation ordering, layouts and inbox identity before dropping its subtype table. Orphan membership rows block migration rather than disappear. Default-model preference migration must never overwrite per-conversation Durable selections.
- Default workspace label migrations must match its stable ID and old seeded name, preserving custom names and membership/layout state. Pin its navigation order explicitly: SQLite NULL order indices sort before the seeded -1.
